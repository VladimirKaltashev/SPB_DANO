# Архив: аудит наблюдаемых заправок

Диагностика остановлена на требуемом первом шаге: очищенный order_id надёжно
идентифицирует заказ, но не гарантирует отдельную физическую заправку / посещение.
Близкие по времени разные заказы встречаются и у клиентов с одной машиной;
без сессии или подтверждённого правила объединения они неоднозначны.

[Отчёт и решение](outputs/diagnostic_summary.md),
[числа аудита](outputs/transaction_audit.json),
[примеры исходных заказов](outputs/examples_single_car.csv).

Запуск из корня проекта:

```bash
.venv/bin/python archive_vehicle_sensitivity_analysis/refueling_behavior/diagnostic.py
```

Новых регрессий, графиков, моделей штрафов и Stage 2 нет. Все предыдущие файлы
сохраняются и проверяются по перечню и SHA-256. Временные окна в аудите не
используются для объединения заказов или изменения существующей очистки.
