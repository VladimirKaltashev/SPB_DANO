# Поведенческие группы водителей

## Первый запуск на другом компьютере

Нужны Git и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Все команды выполняются в терминале; активировать виртуальное окружение вручную
не нужно. Python 3.12 указан в `.python-version`, зависимости — в `uv.lock`.

```bash
git clone https://github.com/VladimirKaltashev/SPB_DANO.git
cd SPB_DANO
uv sync --locked
uv run jupyter nbconvert --to notebook --execute ochistka.ipynb --output ochistka.executed.ipynb --ExecutePreprocessor.timeout=600
uv run python main.py --source processed
```

Очистка читает исходные `clients_demographics.csv`, `fines_2026.csv` и
`fuel_transaction.csv` из корня репозитория и создаёт `data/processed/`.
Исходный ноутбук сохраняется; выполненная копия — `ochistka.executed.ipynb`.
После расчёта откройте `outputs/behavior_cluster_analysis/index.html`
двойным щелчком в файловом менеджере.

Если репозиторий закрытый, владелец должен сначала предоставить доступ на GitHub.
Скачанные отдельно исходные CSV нужно положить в корень проекта с теми же именами.

## Запуск с готовыми очищенными данными

Очищенные CSV в репозитории хранятся через Git LFS. Если вместо таблицы скачался
короткий текст с `version https://git-lfs.github.com/spec/v1`, установите
[Git LFS](https://git-lfs.com/) и выполните:

```bash
git lfs install
git lfs pull
uv sync --locked
uv run python main.py --source processed
```

Повторная очистка через `ochistka.ipynb` из первого примера также создаёт эти таблицы
и не требует загружать их из LFS.

## Повторный запуск

Из папки проекта, когда очищенные данные уже есть:

```bash
uv run python main.py --source processed
```

Откройте `outputs/behavior_cluster_analysis/index.html`: там все общие графики,
расшифровка номеров групп, краткие выводы и подробные графики каждой группы.
PNG также сохраняются отдельно. Графики сохраняются в файлы; окно Matplotlib
при запуске скрипта не открывается.
Папка `outputs/` генерируется локально и не включается в новые коммиты.
Для передачи готового HTML-отчёта отправляйте обе папки
`behavior_cluster_analysis` и `behavior_clustering` вместе, сохраняя их
расположение: HTML ссылается на соседние PNG.

## Что делает код

1. `ochistka.ipynb` и `preprocessing.py` очищают данные и сохраняют
   `data/processed/clients_demographics_clean.csv`, `fines_clean.csv`,
   `fuel_clean.csv` и `client_week_panel.csv`.
2. `data_sources.py` выбирает очищенные таблицы. В режиме `auto`, если их
   нет, используются raw CSV; фактический источник печатается при запуске.
   `--source processed` запрещает такой переход к raw.
3. `spb_clustering.py` агрегирует данные до одной строки на клиента.
   Обучения KMeans и кластеров по стоимости/числу автомобилей больше нет.
4. `behavior_clusters.py` присваивает группы по нарушениям до 1 июня 2026.
   Автомобили используются только для описания и дополнительных тегов.
5. `cluster_analys.py` сравнивает фиксированные группы до/после кризиса,
   строит месячную динамику, сравнение 2025/2026 и детализацию типов нарушений.
6. `report_gallery.py` проверяет созданные изображения и собирает HTML-отчёт.

Недельная панель — клиент по неделям, а таблица групп — клиент.
Они соединяются по `client_id` как many-to-one и сохраняются в
`outputs/behavior_clustering/tables/client_week_panel_with_clusters.csv`.
Экспорт панели можно отключить через `--skip-panel-export`.
Основной анализ рассчитывает показатели из очищенных событий.

## Как назначаются группы

Это правила сегментации, а не обученная модель. Возможные ID:

| ID | Группа | Условие |
|---|---|---|
| 0 | Без недавних нарушений | Нет штрафов 20 марта–31 мая; за 12 месяцев ≤2 |
| 1 | Без новых штрафов, с историей | Нет недавних; за 12 месяцев >2 |
| 2 | Эпизодические нарушители | Остальные клиенты с недавними штрафами |
| 3 | Регулярные любители скорости | ≥2 недавних штрафов, скорость ≥75% |
| 4 | Хронические нарушители | Положительное число исторических штрафов не ниже 90-го перцентиля либо ≥10 недавних |
| 5 | Разноплановые нарушители | ≥3 типов недавних нарушений |
| 6 | Опасные нарушения | Хотя бы один эпизод превышения на 40+ км/ч, красного сигнала или встречной полосы |

При пересечении правил побеждает больший ID. Пересечения сохраняются в
`tag_*`. Пустые категории не создаются: фактических групп может быть меньше семи.
Число групп не задаётся параметром `--clusters`.

## Результаты и повторный запуск

- `outputs/behavior_clustering/` — витрина, назначения групп, правила,
  таблица профилей и два графика размеров/профилей.
- `outputs/behavior_cluster_analysis/` — семь общих PNG, PNG для каждой группы,
  HTML-отчёт, CSV и `analysis_summary.md`.
- `analysis_metadata.json` — источники, периоды, пороги и список проверенных PNG.

```bash
uv run python main.py --source processed
uv run python main.py --skip-clustering
uv run python main.py --skip-behavior-analysis
uv run python behavior_clusters.py
uv run python cluster_analys.py
```

`--skip-clustering` использует сохранённые поведенческие группы.
При отсутствии файла анализ завершается понятной ошибкой.
`--skip-behavior-analysis` создаёт только группы и их два графика.
Другие пути: `--data-dir /path/to/data --output-dir /path/to/outputs`.

## Почему раньше было две схемы и пропадали графики

В `main.py` последовательно запускались KMeans, его анализ, поведенческие
группы и второй анализ. Поведенческая схема зависела от витрины,
созданной вместе с KMeans. Анализ дополнительно мог сам обучать запасной KMeans.
Эти ветки удалены.

Пять общих PNG перечислялись в `OBSOLETE_GRAPH_FILES` и удалялись при запуске.
Функции для них существовали, но не вызывались. Оставались график цены,
тепловая карта нарушений и изображения в подпапке `offence_types`.
Теперь вызываются все построители, а отсутствие Matplotlib приводит к явной
ошибке. Успешный запуск означает, что изображения созданы и проверены.

## Как читать анализ

Частоты нормированы на 30 дней. В сравнении до/после используются клиенты,
подключённые до начала общего периода наблюдений. По каждой метрике сравниваются
те же клиенты; пропущенные значения исключаются попарно.
Проверяется среднее изменение, применяется поправка Benjamini–Hochberg.
По умолчанию нужны ≥40 клиентов, q≤0.05 и размер эффекта ≥0.20 по модулю.
Нехватка данных обозначается «н/д».

Годовое сравнение — апрель–август 2025 и 2026 по всей базе. По типам нарушений
за 2025 год детализации нет, если не предоставлен отдельный CSV.
Это описательный анализ: сезонность, длительность наблюдения и возврат
к среднему могут объяснять часть изменений. Региональная модель с контрольными
переменными и оценка причинного эффекта кризиса здесь пока не реализованы.
