# Структура и главный пайплайн

## Единственный основной запуск

```bash
uv run python main.py
```

Команда последовательно выполняет:

1. `data/raw/*.csv` → проверяемая очистка;
2. сохранение очищенных строк и недельной панели в `data/processed/`;
3. построение докризисных групп водителей;
4. проверку текущей гипотезы на изменениях до/после 1 июня;
5. дополнительный помесячный отчёт по категориям штрафов.

Ни один ноутбук для основного запуска не требуется.

## Python-файлы активного контура

### Корень

- `main.py` — единственная главная точка входа. В нём нет аналитической логики:
  он только запускает этапы в правильном порядке.

### `pipeline/`

- `clean_data.py` — единственная реализация очистки и создания недельной панели.
- `preprocessing.py` — низкоуровневые правила обработки дублей, возвратов топлива
  и аудита качества; вызывается из `clean_data.py`.
- `data_sources.py` — выбирает raw/processed источники и добавляет группы к панели.
- `plotting.py` — единая настройка Matplotlib для сохранения графиков без GUI.
- `report_gallery.py` — проверяет PNG и собирает HTML-галерею.

### `current_hypothesis/`

- `run_analysis.py` — запускает только текущую гипотезу без повторной очистки.
- `prepare_clients.py` — агрегирует докризисные признаки до клиента.
- `define_groups.py` — назначает докризисные поведенческие группы.
- `check_hypothesis.py` — сравнивает показатели тех же клиентов до/после отсечки.

### `supporting_analysis/`

- `monthly_offences.py` — дополнительный описательный анализ типов штрафов.
  Это не отдельная подтверждённая гипотеза.
- `build_monthly_deck.mjs` — необязательная сборка редактируемого PowerPoint.

### `tests/`

Автотесты очистки источников, назначения групп, проверки текущей гипотезы и
помесячного анализа. Эти файлы не участвуют в рабочем запуске.

## Ноутбуки

- `notebooks/cleaning.ipynb` — короткая демонстрационная оболочка над
  `pipeline.clean_data.run_cleaning()`. Отдельной логики очистки в нём нет.
- `notebooks/behavior_clustering.ipynb` — оболочка для запуска текущей гипотезы
  и просмотра её таблиц и графиков.
- `archive_exploratory_notebooks/` — старые исследовательские ноутбуки; основной
  пайплайн их не вызывает.

## Что такое `client_week_panel_v2.csv`

Старый файл перенесён в `data/reference/client_week_panel_v2.csv`. Это
контрольный снимок, а не вход анализа. Его 27 основных колонок полностью
совпадали с воспроизводимой панелью на всех 590 525 строках; шесть остальных
колонок теперь также рассчитываются в `pipeline/clean_data.py`.

При запуске `main.py` новая панель сохраняется как
`data/processed/client_week_panel.csv`. Все 27 базовых колонок автоматически
сверяются с контрольным снимком, а формулы шести производных колонок проверяются
автотестом.

## Данные и результаты

- `data/raw/` — три исходных CSV; код их не перезаписывает.
- `data/processed/` — полностью воспроизводимые очищенные таблицы.
- `data/reference/` — старый контрольный снимок v2, не используемый как вход.
- `outputs/` — отчёты, таблицы и графики; папка генерируется заново.
- `archive_*` — остановленные или неподтверждённые исследовательские ветки.
