# Штрафы по месяцам и категориям

После очистки и основного расчёта (`uv run python main.py --source processed`):

```bash
uv run python monthly_offences.py
```

Параметры:

```bash
uv run python monthly_offences.py --data-dir /path/to/SPB --output-dir outputs/monthly_offences --start 2026-04-01 --crisis-start 2026-06-01 --end 2026-09-01 --top-n 5
```

`--end` исключается. Начало и конец должны ограничивать полные месяцы.
Источник штрафов строго `data/processed/fines_clean.csv`. Март не подмешивается
из необработанного файла: в очищенном источнике его нет.
Сохранённые группы читаются из `outputs/behavior_cluster_analysis/client_behavior_features.csv`.
Их можно передать явно через `--clients-file`.

## Результаты

- `figures/cluster_0_total.png` ... `cluster_6_total.png`: все категории, абсолютное число штрафов по месяцам.
- `figures/cluster_0_categories.png` ... `cluster_6_categories.png`: составные столбцы с топ-5 категорий и остатком. Топ фиксируется за весь период, а не меняется каждый месяц.
- `figures/cluster_focus_*_category_focus.png`: телефон, стоп-линия, ремень, платная дорога. Здесь одна и та же когорта, частота на 1 000 клиентов за 30 дней.
- `monthly_totals.csv`: абсолютные количества по группе и месяцу.
- `monthly_categories.csv`: все 25 исходных категорий, включая явные нулевые клетки.
- `category_dictionary.csv`: полные названия, сокращённые подписи и широкие семейства.
- `category_pre_post.csv`: сравнение каждой конкретной категории, а не неопределённого «числа штрафов».
- `category_appearances.csv`: категории с нулём до и событиями после. `zero_baseline_reason` отделяет отсутствие событий от нуля, заданного классификатором.
- `family_pre_post.csv`: дополнительное сравнение широких семейств. Исходные категории не теряются.
- `monthly_anomalies.csv`: описательный поиск помесячных скачков.
- `category_crisis_sensitivity.csv`: сравнения для границы кризиса за 14 дней до и после основной даты.
- `deck_data.json`: все числа для редактируемых диаграмм PowerPoint.

## Значение колонок «до/после»

`category` всегда содержит полное название. `cluster_id = -1` означает всех
клиентов сопоставимой когорты без разбиения. `pre_count` и `post_count` являются
числами уникальных `bill_id`, а не суммами рублей. Их нельзя прямо сравнивать:
в базовом запуске до кризиса 61 день, после 92 дня.

`pre_per_1000_clients_30d` и `post_per_1000_clients_30d` учитывают эту разницу.
`change_pct` относится к этим частотам. `pre_clients_with_fines` и
`post_clients_with_fines` показывают охват событиями, а не число штрафов.
Когорта включает клиентов, подключившихся не позднее начала периода.
Дата подключения не гарантирует полноту наблюдений или одинаковый пробег.

Старое общее «число штрафов» означает сумму **всех категорий**. Новая таблица
раскладывает этот показатель на конкретные категории.

## Проверка роста и ограничений

Статистическая проверка: парный t-тест разницы дневных частот внутри клиента.
Поправка Benjamini-Hochberg применяется отдельно к общему анализу категорий
и совместно ко всем пригодным клеткам «группа-категория».
Для широких семейств поправка отдельная. Это разведочный анализ.

Критерий `sharp_growth`: рост минимум на 50%, q < 0.05, прибавка минимум
1 штраф на 1 000 клиентов за 30 дней, минимум 10 клиентов со штрафом после.
В тест допускаются клетки с минимум 10 событиями и 5 клиентами в каждом окне
при размере группы не меньше 40. Группы 0/1 исключаются из проверки общих
ростов: их базовый ноль задаёт классификатор. При нулевой базе процент роста
и тест отсутствуют, вместо бесконечного роста.

Все остальные группы также зависят от базовых нарушений. Поэтому p/q не
устраняют смещение отбора. Для причинной гипотезы нужны независимая
историческая сегментация, сравнение регионов и данные о реальном дефиците.
В источнике нет ДТП и пробега. Отсутствие записи трактуется как ноль событий,
но само по себе не доказывает идеальное вождение.

Аномалия `monthly_jump`: дневная частота растёт минимум вдвое относительно
предыдущего месяца при минимум 10 событиях до и 20 после. Это описательный
фильтр, без теста значимости. Доля крупнейшего клиента позволяет проверить,
не вызван ли скачок одним человеком. Все такие проверки используют фиксированную когорту.

## PowerPoint

`build_monthly_deck.mjs` собирает **редактируемые** диаграммы из JSON.
Он использует среду Codex с `@oai/artifact-tool` и установленным навыком
Presentations. Python-расчёт и PNG работают независимо от этой среды.

```bash
node build_monthly_deck.mjs outputs/monthly_offences/deck_data.json outputs/monthly_offences/monthly_fines.pptx
```

Среде сборки нужны `PRESENTATIONS_SKILL_DIR`, `RUNTIME_NODE_MODULES`,
`RUNTIME_PYTHON` из доступной установки Codex. Модуль `@oai/artifact-tool`
должен разрешаться через `node_modules`. `TASK_WORKSPACE` по умолчанию равен
текущему каталогу. Сборщик проверяет пакет PPTX и встраивает отдельные книги
с данными для изменения диаграмм в PowerPoint. Для повторной сборки нужно
дать новый выходной путь. Красная линия на PNG стоит по оси даты точно,
а в PowerPoint является редактируемой приблизительной аннотацией.

## Тесты

```bash
uv run --with pytest python -m pytest test_monthly_offences.py -q
```

Проверяются дубли постановлений, конфликты, неизвестные клиенты, нулевые
месяцы, нулевая база, поправка на множественные сравнения и разная длина окон.
